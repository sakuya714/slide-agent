# slide-kit 設計書（v0.3）

2026-11-17。v0.1（deck-hub 案）にユーザーのレビューを反映し、v0.2 の「今回作る」を実装した。

実装で変えたこと：コマンドの本体は `bin/slide`（リポジトリ直下に `slide` ファイルを置くと資料フォルダ `slide/` と名前がぶつかるため）。

---

## 1. 目的

**秘書（AI）が HTML でスライドを作る → ユーザーがブラウザで直す → PDF / PowerPoint で編集できる PPTX に書き出す。** これを1つのアプリで、一生使える形にする。

```
秘書が作る ──→ ユーザーが直す ──→ 秘書がさらに直す ──→ … ──→ PDF / PPTX
  (deck.html を書く)  (slide-kit の画面)    (同じ deck.html を書く)
```

- 正本は資料ごとに **deck.html 1つだけ**。秘書もユーザーも同じファイルを直す。PDF・PPTX は毎回そこから作るコピー
- Mac の中だけで動くアプリ（`127.0.0.1`）。GitHub Pages では公開しない（保存・書き出しにサーバーが要る／資料は誰にも見せない）

### 作らないもの
クラウド保存・共同編集／スマホでの編集／アニメーションの書き出し／Google スライド・Keynote への書き出し／GitHub Pages での公開

## 2. 名前・置き場所

| もの | 名前・場所 |
|---|---|
| アプリ | **slide-kit**（`（親フォルダ）/slide-kit/`、GitHub `sakuya714/slide-kit`、public） |
| 起動コマンド | **`slide`**（サーバーを起動してブラウザで開く） |
| ユーザーのもの | **`slide-kit/slide/`**（`.gitignore` で除外。GitHub に上がらない） |
| 資料 | **`slide/deck/{フォルダ}/{資料名}/`**（deck.html・assets/。サイドバーに出るのはここ） |
| 書き出し先 | **`slide/final/{フォルダ}/{資料名}.pdf・.pptx`**（v0.3 でリポジトリの外から中へ移した。全部 `slide/` の中で完結させるため） |

```
（親フォルダ）/
├── slide-kit/                    ← GitHub（public）。上がるのはアプリのコードだけ
│   ├── bin/slide                 コマンド（~/.local/bin/slide からリンク）
│   ├── server/                   ローカルサーバー（Python）
│   ├── editor/                   画面（HTML / CSS / JS。ビルド不要）
│   ├── theme/                    資料の見た目（色・フォント・部品）
│   ├── export/                   PDF・PPTX 変換
│   ├── docs/                     design.md（これ）・FORMAT.md（秘書向けの書き方）
│   └── slide/                    ← .gitignore。ユーザーのものは全部ここ
│       ├── deck/                 資料の本体（サイドバーに出るのはここ）
│       │   ├── 営業/
│       │   │   └── 〇〇社_提案/
│       │   │       ├── deck.html 正本
│       │   │       └── assets/   画像
│       │   └── 大学/ …
│       └── final/                完成品：書き出した PDF・PPTX（中は deck/ と同じ階層）
│           └── 営業/〇〇社_提案.pdf・.pptx
```

### 資料が漏れないための仕組み（2重）
1. `.gitignore` で `slide/` を除外
2. pre-commit フック：`slide/` の中のファイルが commit に入ったら止める（`.gitignore` の書き間違いや `git add -f` への保険）

資料（`slide/deck/`）も書き出し（`slide/final/`）も `slide/` の中なので、同じ2重の仕組みで守られる。

## 3. 画面

```
☰ を押すとサイドバー                メイン画面
┌────────────────┐┌─────────────────────────────────────────────┐
│ slide-kit        ││ ☰  〇〇社_提案  ● 保存済み            ↶ ↷  64% │
│                  │├────────┬─────────────────────────┬──────────┤
│ ▾ 営業    ││ ＋ 追加 │ スライド3 › カード › 見出し │ 文字色    │
│   ▸ 〇〇社_提案   ││ ┌────┐ │ ┌─────────────────────┐ │ 背景色    │
│   ▸ △△社_営業   ││ │ 1  │ │ │                     │ │ 大きさ    │
│ ▸ 大学           ││ └────┘ │ │  編集中のスライド      │ │ 太さ・揃え │
│                  ││ ┏━━━━┓ │ │                     │ │ ─────── │
│ ＋ 新しい資料     ││ ┃ 2  ┃ │ └─────────────────────┘ │ スライド   │
│                  ││ ┗━━━━┛ ├─────────────────────────┤ 背景      │
│ ──────────────  ││  …     │ 発表者ノート               │ ─────── │
│ [ PDF ] [ PPTX ] ││        │                          │ テーマ色   │
└────────────────┘└────────┴─────────────────────────┴──────────┘
```

- **サイドバー**（☰ で開閉）：notebook-hub と同じ階層表示で `slide/deck/` の中身を出す。資料を押すとメイン画面で開く。一番下に **PDF・PPTX ボタン**（今開いている資料を書き出す。終わったら「Finder で開く」を出す）
- **メイン画面の左**：開いている資料のスライド一覧（追加・複製・削除・ドラッグで並べ替え）
- **真ん中**：スライド本体。クリックで部品を選ぶ、ダブルクリックで文字を直す。上に部品の場所（スライド3 › カード › 見出し）を出し、押すと親の部品を選べる
- **右**：1枚のパネル（要素 → スライド → テーマ の順に並べる。項目が少ないのでタブにしない）
- **下**：発表者ノート
- 見た目：濃いニュートラルグレー。資料が一番目立つように、画面側は控えめに

## 4. 機能

### 今回作る
| 分類 | 機能 |
|---|---|
| 開く | `slide` で起動 → ブラウザが開く／サイドバーで資料を選ぶ／＋で新しい資料（フォルダと空の deck.html を作る） |
| 保存 | 自動保存（直して1秒後。`Cmd+S` でも）／直前の版を1つだけ `.deck.bak.html` に残す |
| 秘書との往復 | 秘書が deck.html を直したら、開いている画面に自動で反映（2秒ごとに更新を確認） |
| スライド | 追加・複製・削除・並べ替え |
| 部品 | クリックで選ぶ／親へ移る／ダブルクリックで文字を直す／文字色・背景色・文字の大きさ・太さ・揃え |
| 資料全体 | スライドの背景／テーマ色の一括変更 |
| その他 | 元に戻す・やり直し（`Cmd+Z` / `Cmd+Shift+Z`）／発表者ノート |
| 書き出し | PDF／**PowerPoint で編集できる PPTX**。サイドバーのボタンと、コマンド（`slide pdf` / `slide pptx`）の両方 |
| チェック | `slide check`（コマンドだけ。秘書が作ったら必ず通す）：文字のはみ出し・スライドの外の部品・画像切れ・小さすぎる文字・PPTX で画像になる部品 |
| 秘書向け | `docs/FORMAT.md`（deck.html の書き方）／秘書の playbook（「資料作って」→ FORMAT.md を読む → 作る → チェック） |

### 今回は作らない（必要になったら足す）
- **画面の中で AI に頼む**（スライドを選んで「もっと短く」→ 裏で Claude Code が直す）← 次の目玉
- テンプレート・レイアウトの充実（ユーザーが後で決める。今回は default テーマ1つ）
- 部品のドラッグ移動・サイズ変更／HTML の直接編集／画像のドラッグ＆ドロップ
- 発表モード／PNG 書き出し／チェックの画面表示／履歴を何世代も残す

## 5. 仕組み

### 5-1. deck.html の形
```html
<!doctype html>
<html lang="ja">
<head>
  <style data-kit="theme">/* テーマの CSS をまるごと埋め込む（このファイル1つで表示できる） */</style>
  <style data-kit="vars">:root{ --ink:#13232D; --accent:#C24F3E; … }</style>
</head>
<body>
  <section class="slide" data-bg="dark">
    <p class="eyebrow">〇〇ビジネスコンテスト 2026</p>
    <h1>AI が作って、<em>人が仕上げる。</em></h1>
    <img src="assets/cover.jpg" class="bg">
    <aside class="notes">ここで話すこと</aside>
  </section>
  <section class="slide">…</section>
</body>
</html>
```
- 1スライド＝1つの `<section class="slide">`。大きさは 1280×720 で固定
- 色はテーマの変数（`var(--accent)`）で書く。直書きしない（テーマ色を変えたら全体が変わるように）
- 編集画面が付ける目印は保存時に全部外す。秘書が読む deck.html はいつもきれいな HTML のまま
- ブラウザでそのまま開いても読める

### 5-2. アプリ
- サーバー：Python（FastAPI・uv で管理）。`127.0.0.1:8770` だけで動く（notebook-hub の 8765 とぶつけない）
- 画面：素の JavaScript（React 等は使わない）。ビルド不要なので、何年たっても動き、秘書も直しやすい
- 資料は画面の中の iframe に読み込む。アプリの見た目と資料の見た目が混ざらない
- 元に戻す：直すたびにそのスライドの HTML を控えておく方式（単純で壊れにくい）

### 5-3. 書き出し
**PDF**：Mac の Google Chrome を裏で動かして（Playwright）、1280×720 のページを1枚ずつ印刷。画面と同じ見た目で、フォントも埋め込まれる。

**PPTX（PowerPoint で編集できる形）**：Chrome で資料を表示して部品ごとに位置・文字・色を読み取り、python-pptx で PowerPoint の部品に置き直す。

| HTML | PowerPoint |
|---|---|
| 文字（見出し・段落・箇条書き） | テキストボックス（色・太さ・大きさを1文字単位で再現） |
| 背景色・枠線・角丸のある箱 | 図形 |
| 画像 | 画像（トリミングも再現） |
| SVG の図・グラデーション・影など | その部分だけ画像にして貼る |
| 発表者ノート | ノート |

- 1280px ＝ PowerPoint の 16:9 の幅にぴったり（1px ＝ 9525 EMU）
- PowerPoint は日本語の改行位置が Chrome と少し違うので、テキストボックスの幅に少し余裕を持たせる
- 相手のパソコンに無いフォントは置き換わるので、テーマに「PPTX で使うフォント」（游ゴシック等）を決めておく
