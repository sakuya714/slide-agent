# slide-kit 設計書（v0.4）

2026-11-17。v0.1〜v0.2 で決めた形を実装し、置き場所を `private/`（deck・final・rules）にまとめた。

---

## 1. 目的

**AI が HTML でスライドを作る → ユーザーがブラウザで直す → PDF / PowerPoint で編集できる PPTX に書き出す。** これを1つのアプリで、一生使える形にする。

```
AI が作る ──→ ユーザーが直す ──→ AI がさらに直す ──→ … ──→ PDF / PPTX
 (deck.html を書く)  (slide-kit の画面)   (同じ deck.html を書く)
```

- 正本は資料ごとに **deck.html 1つだけ**。AI もユーザーも同じファイルを直す。PDF・PPTX は毎回そこから作るコピー
- Mac の中だけで動く（`127.0.0.1`）。GitHub Pages では公開しない（保存・書き出しにサーバーが要る／資料は誰にも見せない）
- 作り方の知識は2段：全員共通の `CLAUDE.md`（リポジトリ）と、ユーザーが育てる `private/rules/`

### 作らないもの
クラウド保存・共同編集／スマホでの編集／アニメーションの書き出し／Google スライド・Keynote への書き出し／GitHub Pages での公開

## 2. 置き場所

```
slide-kit/                     ← GitHub（public）。上がるのはアプリだけ
├── CLAUDE.md                  AI 向けの説明書（作る流れ・deck.html の書き方・rules の読み方。作り方は全部ここ）
├── docs/design.md             これ
├── bin/slide                  コマンド（~/.local/bin/slide からリンク）
├── server/                    ローカルサーバー（Python / FastAPI）・CLI
├── editor/                    画面（HTML / CSS / JS。ビルド不要）
├── theme/                     資料の見た目（色・フォント・部品）とひな形
├── export/                    PDF・PPTX 変換とチェック
├── hooks/pre-commit           private/ を commit させない
└── private/                   ← .gitignore。ユーザーのものは全部ここ
    ├── deck/{フォルダ}/{資料名}/   作業中の資料（deck.html・assets/）。サイドバーに出る
    ├── final/{フォルダ}/{資料名}.pdf・.pptx   完成品
    └── rules/                 ユーザーが育てる AI 向けの指示（直下＝全資料共通、{フォルダ}/＝その資料群用）
```

- コマンドの本体を `bin/slide` に置くのは、リポジトリ直下だと資料フォルダと名前がぶつかるため（v0.3 で資料を `slide/` に置いていた名残り。今は `private/` なのでぶつからないが、`bin/` の方が整理として分かりやすいのでそのまま）
- clone した人も `./install.sh` で同じ `private/` ができる。中身はその人のものだけ

### 資料が漏れないための仕組み（2重）
1. `.gitignore` で `private/` を除外
2. pre-commit フック：`private/` の中のファイルが commit に入ったら止める（`.gitignore` の書き間違いや `git add -f` への保険。日本語のファイル名でも効くよう、名前の文字列ではなくパス指定で調べる）

## 3. 画面

```
☰ を押すとサイドバー                メイン画面
┌────────────────┐┌─────────────────────────────────────────────┐
│ slide-kit        ││ ☰  〇〇社_提案  ● 保存済み            ↶ ↷  64% │
│                  │├────────┬─────────────────────────┬──────────┤
│ ▾ 営業           ││ ＋ 追加 │ スライド3 › カード › 見出し │ 部品      │
│   ▸ 〇〇社_提案   ││ ┌────┐ │ ┌─────────────────────┐ │ 文字色・大きさ│
│   ▸ △△社_営業   ││ │ 1  │ │ │                     │ │ 太さ・揃え  │
│ ▸ 大学           ││ └────┘ │ │  編集中のスライド      │ │ 背景色     │
│                  ││ ┏━━━━┓ │ │                     │ │ ─────── │
│ ＋ 新しい資料     ││ ┃ 2  ┃ │ └─────────────────────┘ │ スライド   │
│                  ││ ┗━━━━┛ ├─────────────────────────┤ 地の色・縦位置│
│ ──────────────  ││  …     │ 発表者ノート               │ ─────── │
│ [ PDF ] [ PPTX ] ││        │                          │ テーマ色   │
└────────────────┘└────────┴─────────────────────────┴──────────┘
```

- **サイドバー**（☰ で開閉）：`private/deck/` の中身を階層で出す。資料を押すとメイン画面で開く。一番下に PDF・PPTX ボタン（今開いている資料を `private/final/` に書き出す。終わったら「Finder で表示」）
- **左**：スライド一覧（追加・複製・削除・ドラッグで並べ替え）
- **真ん中**：クリックで部品を選ぶ、ダブルクリックで文字を直す。上に部品の場所（スライド3 › カード › 見出し）を出し、押すと親を選べる
- **右**：部品 → スライド → テーマ色 の順の1枚のパネル
- **下**：発表者ノート

## 4. 機能

### できること
| 分類 | 機能 |
|---|---|
| 開く | `slide` で起動 → ブラウザが開く／サイドバーで資料を選ぶ／＋で新しい資料 |
| 保存 | 自動保存（直して1秒後。`⌘S` でも）／直前の版を `.deck.bak.html` に残す |
| AI との往復 | 外で deck.html が書き換わったら2秒以内に反映。こちらに未保存の変更があるときは「外の変更を読み込む／この画面で上書き」を選ばせる |
| スライド | 追加・複製・削除・並べ替え |
| 部品 | 選ぶ／親へ／文字を直す／文字色・背景色・大きさ・太さ・揃え／複製・削除 |
| 資料全体 | スライドの地の色・縦位置・背景色／テーマ色の一括変更 |
| その他 | 元に戻す・やり直し（`⌘Z` / `⇧⌘Z`）／発表者ノート |
| 書き出し | PDF／PowerPoint で編集できる PPTX（画面のボタンとコマンドの両方） |
| チェック | `slide check`：はみ出し・画像切れ・小さい文字・PPTX で画像になる部分・色の直書き |

### まだ作っていないもの
- **画面の中で AI に頼む**（スライド・部品を選んで「もっと短く」→ 裏で Claude Code が直す）← 次の目玉
- 新しい資料を作るときに、`private/rules/` に合わせた型を選ぶ
- 部品のドラッグ移動・サイズ変更／HTML の直接編集／画像のドラッグ＆ドロップ／発表モード／PNG 書き出し／チェックの画面表示

## 5. 仕組み

### 5-1. deck.html
- 1スライド＝1つの `<section class="slide">`（1280×720 固定）。詳しい書き方は `CLAUDE.md`
- `<style data-kit="theme">`（テーマ。資料に埋め込むので、このファイル1つで表示できる）と `<style data-kit="vars">`（テーマ色）を持つ
- 編集画面が付ける目印（選択中・編集中など）は保存時に全部外す。AI が読む deck.html はいつもきれいな HTML のまま

### 5-2. アプリ
- サーバー：Python（FastAPI・uv で管理）。`127.0.0.1:8770` だけで動く
- 画面：素の JavaScript。資料は iframe に読み込み、その DOM を直接いじる。元に戻すは「直すたびに本文の HTML を控える」方式
- 外からの変更：画面が2秒ごとにファイルの版（更新時刻）を確認する。保存時に版が食い違えば上書きせず確認を出す

### 5-3. 書き出し
**PDF**：Mac の Google Chrome を裏で動かして（Playwright）、1280×720 のページを1枚ずつ印刷。画面と同じ見た目で、フォントも埋め込まれる。

**PPTX**：Chrome で資料を表示して `export/extract.js` が部品ごとに位置・文字・色を読み取り、`export/pptx.py`（python-pptx）が PowerPoint の部品に置き直す。

| HTML | PowerPoint |
|---|---|
| 文字（見出し・段落・箇条書き） | テキストボックス（色・太さ・大きさを1文字単位で再現。箇条書きは PowerPoint の箇条書き） |
| 背景色・枠線・角丸のある箱、片側だけの線 | 図形 |
| 画像 | 画像（`object-fit: cover` のトリミングも再現） |
| SVG・グラデーション・影・回転・表・角丸の写真 | その部分だけ画像（2倍の解像度） |
| 発表者ノート | ノート |

- 1280px ＝ PowerPoint の 16:9 の幅（1px ＝ 9525 EMU）
- PowerPoint は日本語の改行位置が Chrome と少し違うので、複数行のテキストボックスは幅を4%広げる。1行のものは折り返さない
- フォントは `--pptx-font-sans` / `--pptx-font-serif`（游ゴシック・游明朝）に置き換える
